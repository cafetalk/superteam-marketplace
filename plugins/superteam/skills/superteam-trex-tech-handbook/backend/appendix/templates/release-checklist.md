# 发布 Checklist 模板

> **流程** 见 `common/04-ci-and-release.md`。本文件是发布单模板，复制填写后贴 Linear 发布 issue comment（或与本批 dev 上的 issue 关联）。

---

## 发布单 — `<service-name>` `<version>` `<YYYY-MM-DD>`

### 1. 版本号
`v<x.y.z>`（语义化版本）

### 2. 变更类型
- [ ] `feature` — 新功能
- [ ] `hotfix` — 紧急修复
- [ ] `chore` — 杂项 / 依赖升级
- [ ] `release` — 周期性版本发布

### 3. 发布时间
`YYYY-MM-DD HH:MM`（必须落在 `common/04` §发布窗口允许的时段内）

### 4. 值班人
@`<gitlab-handle>`（发布全程在线，5 分钟内响应 P0）

### 5. 回滚负责人
@`<gitlab-handle>`（可与值班人同人）

### 6. 包含 MR
- `<MR URL>` — `<标题>` — Linear `TREX-<id>`
- `<MR URL>` — `<标题>` — Linear `TREX-<id>`

### 7. 风险评估

| 维度 | 是 / 否 | 说明 |
|---|---|---|
| DB 表结构变更 | ☐ | （如是，附迁移脚本 + 逆脚本） |
| OTS 表 / 索引变更 | ☐ | （如是，附变更步骤） |
| Nacos 配置变更 | ☐ | （如是，附 key + diff） |
| Dubbo 接口契约变更 | ☐ | （如是，列消费方 + 通知确认） |
| OpenAPI / GraphQL schema 变更 | ☐ | （如是，前端 / SDK 同步状态） |
| 跨服务影响 | ☐ | （如是，列受影响服务） |
| 不可逆操作 | ☐ | （如是，明确风险与缓解） |

### 8. 灰度策略

**维度**：
- [ ] 按比例（5% → 20% → 50% → 100%）
- [ ] 按用户（内部 → beta → 全量）
- [ ] 按 region（指定 region → 多 region）
- [ ] 按实例 / 机器（一台 → 一组 → 全集群）

**各阶段观察时长**：`<N>` 分钟（≥ 5）

**评估指标**：
- 错误率（5xx / 业务错误码）
- P99 / P95 延迟
- 业务核心指标（按服务定义）

### 9. 回滚条件

| 指标 | 阈值 |
|---|---|
| 错误率 | > `<X>` % |
| P99 延迟 | > `<Y>` ms（或环比 +`<%>`%） |
| 业务指标 `<name>` | `<异常定义>` |
| 用户反馈 | `<N>` 起 / `<时段>` |

### 10. 回滚动作

| 项 | 内容 |
|---|---|
| 镜像回退到 | `v<prev-version>` |
| Nacos 配置回滚 | `<key 列表>` → prev 版本 |
| DB 迁移逆操作 | `<脚本路径 / 手动步骤>` |
| Dubbo / API 契约回退 | `<消费方通知 + 步骤>` |
| 切流量手册 | `<链接 / 步骤>` |

### 11. 发布前 checklist【强制】

- [ ] dev → master MR 已 merge
- [ ] CI 通过（含 lint / unit / build）
- [ ] 研发负责人已 approve 发布 MR（`beta_*` → `master`）
- [ ] Ops 已 approve MR
- [ ] 提测单 sign-off（见 `common/07`）
- [ ] P0 / P1 bug 全部 close
- [ ] 关联 PRD / 设计文档已更新
- [ ] On-call / 值班人已知会
- [ ] 数据库迁移已在 pre / test 验证（如适用）
- [ ] 回滚预案已 dry-run 验证（如条件允许）

### 12. 发布后 checklist【强制】

- [ ] 各灰度阶段错误率正常（< 阈值）
- [ ] 各灰度阶段 P99 正常
- [ ] 业务核心指标正常
- [ ] 告警规则已生效（新增 / 调整的告警）
- [ ] 业务侧验证通过（PM / 业务方反馈）
- [ ] Linear **发布 issue** 更新到 `Done`（本批 dev issue 在提测 MR merge 时已 Done，本步不重复处理；如发布过程中开发者补充修复，记到 sub-issue 或 follow-up issue）
- [ ] 发布完成通告（频道 / 群）

---

`〔填写约定〕`
- 1–12 都是【强制】字段
- 7–10 表格中"是 / 否"列必须勾选；"否"也是有效信息（明确无相关风险）
- 11–12 checklist 项必须**实际验证**，不允许批量打勾
- 发布过程中实时更新（如灰度卡在 20% 阶段，本单要说明原因 + 决策）
- 发布完成后**保留**在 Linear / 文档库归档（用于事后回顾 + 经验沉淀）
